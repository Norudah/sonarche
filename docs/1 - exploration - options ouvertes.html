01 — Cadrage

Ce qu'on construit, ce qu'on repousse

Le MVP attaque la vraie douleur — métadonnées et pochettes — sans se fracasser sur le verrou iOS. L'étape « glisser vers Musique » reste manuelle et assumée.

◆ Dans le MVP

  • Téléchargement depuis YouTube — avec réglage du parsing des titres
  • Tagging automatique + pochette carrée — via MusicBrainz
  • Bibliothèque locale = source de vérité
  • Vue « ma lib » lue depuis la base beets
  • Import manuel dans Musique → sync iPhone

◇ Repoussé plus tard

  • Serveur perso de streaming — « Spotify maison »
  • App / client iPhone dédié
  • Transfert automatisé vers le téléphone — bloqué par Apple
  • Distribution grand public / multi-OS soignée

04 — Décisions

Les choix, et le pourquoi

Chaque arbitrage a une raison — et souvent une option écartée qui en dit autant.

Format audio m4a / AAC natif

La source YouTube est déjà lossy. On prend le flux AAC tel quel — zéro réencodage, lit partout dans l'écosystème Apple.

écarté · MP3 (réflexe 2010) · FLAC (inutile, source dégradée)

Métadonnées Bases ouvertes, gratuites

MusicBrainz, Cover Art Archive, AcoustID, iTunes. C'est l'anti-Spotify que tu cherches : tu récupères les données, tu ne les loues pas.

coût total · 0 €

Communication interne stdio · NDJSON (natif)

Aucun port réseau ouvert, ressenti natif, surface d'attaque nulle. Un peu de protocole maison, que je porte.

écarté · serveur HTTP local (port qui traîne, à sécuriser)

Packaging Python Interpréteur embarqué + uv

python-build-standalone + environnement verrouillé. Un vrai Python → les plugins beets se chargent tout seuls.

écarté · PyInstaller (imports dynamiques → « plugin introuvable »)

Téléchargement Binaires officiels standalone

yt-dlp et ffmpeg publient leurs propres binaires. La moitié « download » de l'app n'a besoin d'aucun Python.

bonus · mise à jour indépendante de yt-dlp

Expérience de setup Premier lancement intelligent

App légère qui télécharge interpréteur + binaires au 1er démarrage, avec écran de progression. Permet l'auto-update de yt-dlp.

condition · nécessite le réseau au 1er lancement

05 — Risques & paris

Où ça peut coincer

Le risque n'est pas « est-ce faisable » — c'est « à quel point c'est élégant à installer ». Classé par ce qu'il faut surveiller en premier.

Pari n°1

Embarquer Python proprement

Le morceau le plus casse-gueule. À valider en tout premier via un spike, avant toute UI. Si ça passe, le reste n'est que du travail.

Cœur de valeur

Le matching interactif (stateful)

« Voici les candidats » → l'utilisateur choisit → « applique ». Décider si le Python garde une session ouverte. La vraie UX à soigner.

À cadrer

Cycle de vie du sidecar

Bug desktop classique : le process Python reste orphelin à la fermeture. Doit être lié au parent et tué proprement.

Récurrent

yt-dlp qui casse

YouTube change ses signatures souvent. Sans mécanisme d'auto-update du binaire, l'app meurt en quelques mois.

06 — Filet de sécurité

Tu ne peux pas être bloqué

Trois niveaux de repli sur le packaging. Le pire cas reste trivial et compatible avec ton usage perso.

1

Python embarqué (uv / standalone)

La cible : robuste, prévisible, aucune install requise côté utilisateur.

↓ si trop galère
2

Python requis sur la machine

Filet de MVP. Moche à distribuer, mais parfait pour « moi et des potes que je dépanne ».

↓ si un jour tu veux distribuer proprement
3

Réécriture native, sans beets

Tagging en Rust contre les API MusicBrainz / AcoustID. Zéro Python, packaging trivial — mais gros chantier. Pour plus tard.

07 — Horizon

Le jour où le « transfert iPhone » disparaît

◇ Vision long terme

La feature 4 (serveur perso) rend la feature 3 (transfert de fichiers) obsolète — et la résout mieux. Un serveur Navidrome exposant l'API Subsonic te donne accès à ta lib depuis des clients iPhone existants et matures (Amperfy…), avec cache offline.

Tu ne transfères plus rien : tu streames, et le client télécharge ce que tu veux écouter hors-ligne. Tu contournes totalement le verrou Apple — sans app custom, sans 99 $/an, sans Finder. Ce qui était « la cerise » devrait, à terme, devenir le pilier.
