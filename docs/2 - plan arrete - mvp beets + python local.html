Music Manager — plan arrêté

Une app de bureau qui télécharge, tague proprement et range ta musique. Le moteur est beets ; le MVP s'appuie sur un Python local isolé. Voici le plan sur lequel on démarre.

Tauri + React Moteur beets Python local · venv isolé Format m4a / AAC + plugin VGMdb (OST jeux) Coût API 0 €

◆ Ce qui a bougé depuis la v1

  • beets est confirmé — (v1 : « pari beets vs moteur natif », indécis). On ne réinvente pas la roue.
  • MVP = Python requis en local, isolé dans un venv — (v1 : Python embarqué dès le départ). Plus simple pour démarrer.
  • Le moteur natif est repoussé loin — (v1 : envisagé comme plan A possible). Il reste un horizon, pas une option MVP.
  • Couverture OST jeux vidéo validée — MusicBrainz + plugin beets-vgmdb pour les cas pointus (titres japonais, pochettes VGM).

04 — Décisions arrêtées

Les choix, et le pourquoi

Chaque arbitrage a une raison — et souvent une option écartée qui en dit autant.

Moteur de tagging beets — confirmé

Mûr depuis des années, écosystème de plugins. Le plugin beets-vgmdb couvre même les OST de jeux (titres japonais, pochettes VGM).

écarté (pour l'instant) · moteur natif Rust — trop de valeur à reconstruire

Exécution de beets Python local, venv isolé

L'app crée son propre environnement et y installe beets. On dépend du Python de l'user juste pour amorcer — ensuite tout est à nous.

interdit · pip install global (casse le système · bloqué par PEP 668)

Format audio m4a / AAC natif

La source YouTube est déjà lossy. On prend le flux AAC tel quel — zéro réencodage, lit partout dans l'écosystème Apple.

écarté · MP3 (réflexe 2010) · FLAC (inutile ici)

Métadonnées Bases ouvertes, gratuites

MusicBrainz, Cover Art Archive, AcoustID, VGMdb, iTunes. L'anti-Spotify : tu récupères les données, tu ne les loues pas.

coût total · 0 € · une seule clé (AcoustID) optionnelle

Communication interne stdio · NDJSON (natif)

Aucun port réseau ouvert, ressenti natif, surface d'attaque nulle. Un peu de protocole maison, que je porte.

écarté · serveur HTTP local (port qui traîne, à sécuriser)

Téléchargement Binaires officiels standalone

yt-dlp et ffmpeg publient leurs propres binaires. Embarqués + auto-update de yt-dlp (il casse souvent quand YouTube change).

bonus · mise à jour indépendante

05 — Stratégie Python

Comment on dépend d'un Python local sans que ça casse

La clé : un environnement isolé que l'app possède, plus un contrôle de santé qui se répare tout seul. C'est ce qui transforme « fragile » en « auto-réparant ».

Au 1er lancement ONBOARDING

  1. Détecter un Python compatible (python3, py -3, emplacements connus)
  2. Vérifier la version — sinon guider l'install (python.org / brew) puis re-scanner
  3. Créer un venv isolé dans le dossier de l'app
  4. Installer beets + plugins en versions figées (lockfile)
  5. Embarquer fpcalc & ffmpeg

À chaque lancement HEALTH CHECK

  1. Le venv tourne-t-il ? beets s'importe-t-il correctement ?
  2. Si cassé (Python déplacé ou mis à jour → venv orphelin)
  3. Reconstruire le venv automatiquement — une panne mystérieuse devient 20 s de rebuild
  4. Sinon, démarrer normalement
Règle ferme : jamais d'install dans le Python de l'utilisateur. Toujours un venv que l'app possède — ça évite les conflits et le refus externally-managed-environment des Python modernes.

06 — Risques & parades

Où ça peut coincer — et le filet en face

Le risque n'est pas « est-ce faisable » — c'est « à quel point c'est fluide à installer et à maintenir ». Chaque risque a sa parade.

À surveiller

Trouver le bon Python (surtout Windows)

PATH ambigu, stub Microsoft Store, python vs python3.

Parade · sonder plusieurs candidats, et laisser l'user pointer son Python à la main en secours.

« Ça marchait, puis non »

Venv cassé après une màj de Python

Le venv référence l'interpréteur qui l'a créé ; s'il disparaît, le venv meurt.

Parade · health check + reconstruction auto à chaque lancement.

Récurrent

yt-dlp qui casse

YouTube change ses signatures souvent.

Parade · mécanisme d'auto-update du binaire yt-dlp.

Cœur de valeur

Le matching interactif (stateful)

« Voici les candidats » → l'user choisit → « applique ». La vraie UX à soigner.

Parade · écran de validation dédié + fallback tag manuel pour les compils de fan.

Neutralisé

Packaging de Python

Le risque n°1 de la v1 — écarté du MVP : on exige Python plutôt que de l'embarquer. À réactiver seulement le jour du packaging autonome.

Horizon

Le jour où le « transfert iPhone » disparaît

◇ Vision long terme

Un serveur perso (Navidrome exposant l'API Subsonic) te donnerait accès à ta lib depuis des clients iPhone existants et matures (Amperfy…), avec cache offline. Tu ne transfères plus rien : tu streames.

Ça contourne totalement le verrou Apple — sans app custom, sans 99 $/an, sans Finder. Ce qui était « la cerise » deviendrait, à terme, le pilier. Mais d'abord : le MVP local ci-dessus.
